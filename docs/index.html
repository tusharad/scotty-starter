GET/api/tour/path-params/:category/:id

Typed URL Path Parameters

Scotty captures URL pattern variables designated with a colon (e.g. :category, :id) and parses them automatically into Haskell types (Text, Int, UUID). If parsing fails, Scotty throws a parse error handled centrally.

src/App/Api/Tour.hsScotty 0.30 DSL
S.get "/api/tour/path-params/:category/:id" $ do
  category <- S.pathParam "category" :: ActionT AppM Text
  itemId   <- S.pathParam "id"       :: ActionT AppM Int

  S.status status200
  S.json $ object
    [ "concept"  .= ("Path Parameters" :: Text)
    , "category" .= category
    , "id"       .= itemId
    ]

GET/api/tour/query-params?filter=...&limit=...

Optional & Required Query Parameters

Scotty provides S.queryParam for required parameters (throwing QueryParameterNotFound if absent), S.queryParamMaybe for optional parameters (returning Maybe a), and S.queryParams for raw key-value pairs.

src/App/Api/Tour.hsScotty 0.30 DSL
S.get "/api/tour/query-params" $ do
  filterVal  <- S.queryParamMaybe "filter" :: ActionT AppM (Maybe Text)
  limitVal   <- S.queryParamMaybe "limit"  :: ActionT AppM (Maybe Int)
  rawQueries <- S.queryParams

  S.status status200
  S.json $ object
    [ "concept"     .= ("Query Parameters" :: Text)
    , "filter"      .= filterVal
    , "limit"       .= limitVal
    , "raw_queries" .= rawQueries
    ]

POST/api/tour/json-body

Typed JSON Deserialization via Aeson

Using S.jsonData, Scotty streams and deserializes incoming JSON payloads directly into strongly-typed Haskell data records. Malformed JSON automatically triggers the centralized RFC 7807 error handler.

src/App/Api/Tour.hsScotty 0.30 DSL
data TourPayload = TourPayload
  { name   :: !Text
  , role   :: !Text
  , skills :: ![Text]
  } deriving (Generic, FromJSON, ToJSON)

S.post "/api/tour/json-body" $ do
  payload <- S.jsonData :: ActionT AppM TourPayload
  S.status status201
  S.json $ object
    [ "concept" .= ("JSON Deserialization" :: Text)
    , "parsed"  .= payload
    ]

GET/api/tour/headers-and-cookies

Request Headers & Cookie Management

Read incoming request headers (S.header), inspect client cookies (getCookie), set custom response headers (S.setHeader), and set cookies with ease.

src/App/Api/Tour.hsScotty 0.30 DSL
S.get "/api/tour/headers-and-cookies" $ do
  ua <- S.header "User-Agent"
  c  <- getCookie "visited"

  -- Set custom response header and cookie
  S.setHeader "X-Scotty-Powered-By" "Scotty 0.30 (Haskell)"
  setSimpleCookie "visited" "true"

  S.status status200
  S.json $ object
    [ "concept"    .= ("Headers & Cookies" :: Text)
    , "user_agent" .= (fmap TL.toStrict ua)
    , "cookie"     .= c
    ]

GET/api/tour/status-codes/:code

Dynamic HTTP Response Status Codes

Scotty allows returning any valid HTTP status code dynamically via S.status and Network.HTTP.Types.Status.mkStatus.

src/App/Api/Tour.hsScotty 0.30 DSL
S.get "/api/tour/status-codes/:code" $ do
  codeInt <- S.pathParam "code" :: ActionT AppM Int
  let sc = mkStatus codeInt "Custom Status"

  S.status sc
  if codeInt == 204
    then S.raw ""
    else S.json $ object
      [ "concept"     .= ("Status Codes" :: Text)
      , "status_code" .= codeInt
      ]

ERR/api/tour/errors/:type

Centralized Error Boundaries & RFC 7807

Scotty provides S.defaultHandler to catch unhandled exceptions. In Scotty Starter, this converts errors into standard RFC 7807 Problem Details (application/problem+json) with titles, status codes, and diagnostics.

src/App/Middleware/ErrorHandler.hsScotty 0.30 DSL
appErrorHandler :: ScottyException -> ActionT m ()
appErrorHandler = \case
  QueryParameterNotFound p ->
    rfc7807 status400 "Missing Query Parameter" ("Missing: " <> p)
  FailedToParseParameter p ->
    rfc7807 status400 "Parameter Parse Failure" ("Cannot parse: " <> p)
  other ->
    rfc7807 status500 "Internal Server Error" (T.pack (show other))
